# 会派別賛否（votes）

議案詳細ページの「会派の賛否」に出すデータ。出典は立川市議会の広報紙「たちかわ市議会便り」の「各議案等に対する賛否」。

## ファイル

| ファイル | 内容 |
| --- | --- |
| `<会期>.json` | 市議会便りの表を書き起こしたもの（手で作る） |
| `<会期>.sql` | JSON から生成した投入用SQL（Supabase の SQL Editor で流す） |

## 手順

1. 市議会便りの該当ページ（PDF）を開き、表を読み取る
   - 作業用コンテナからは市のサイトに届かないため、ブラウザ内で pdf.js を使い、**文字の位置**と**罫線（セルの境界）**から表を復元する。画面表示でも確認する
   - 議長は表決に加わらない。会派を構成しない議員は登録しない
2. `<会期>.json` を作る（`r8-1-teireikai.json` を参考に）
   - `factions`：表の左からの順に、当時の会派の正式名と略称
   - `split`：賛否が分かれた議案・請願・陳情と、反対した会派（ほかの会派は賛成）。会派内の一部の退席などは `comments` に事実だけ書く（議員名は書かない）
   - `unanimous.billCount`：全員一致の議案の件数（確認用）
   - `unanimous.adoptedPetitions` / `rejectedPetitions`：全員一致で採択／不採択の請願・陳情の番号
   - `notVoted`：継続審査などで、その会期に表決がなかったものの番号
3. SQLを生成する
   ```bash
   pnpm --filter @mirai-gikai/tachikawa-ingest build-votes-sql -- --session r8-1-teireikai
   ```
4. Supabase の SQL Editor に `<会期>.sql` を貼り付けて実行する
   - 件数が JSON と合わないとき（JSON に書いていない請願・陳情が会期内にあるときも）はエラーで止まり、何も変更されない
   - 何度流しても同じ結果になる

## 登録のルール

- 会派は**議決した当時の会派**。今の会派一覧に無い会派は、過去の会派（表示順 101〜、`is_active = false`）として追加する
- 全員一致の議案：全会派「賛成」
- 請願・陳情：全員一致で採択なら全会派「賛成」、不採択なら全会派「反対」（＝採択に反対）。継続審査で表決がなかったものは登録しない
- 会派の一部の議員が退席した場合：出席した議員の賛否で会派の賛否とし、「所属議員○人のうち○人は退席」とコメントを付ける
- 同じ会派の中で賛否が割れた場合：その会派を「賛否が分かれた」とする（第1回定例会では該当なし。該当が出たらツールと表示を追加する）
