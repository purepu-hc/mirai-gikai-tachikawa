# 議案解説の書き方ルール（立川市版）

みらい議会＠立川市の「やさしい（かんたん）版」「くわしい版」の解説を作るときのルールと手順です。
令和8年第3回定例会（議案30件・請願陳情4件）の作成で運営者と合意した内容をまとめています。

## 1. 基本方針

| ルール | 内容 |
|---|---|
| 費用ゼロ | サイト上でAI・外部APIは使わない。下書きはAIとの対話（チャット）の中で作り、SQLにしてSupabaseのSQL Editorで流す |
| 事実だけ | 書くのは**議案書（請願書・陳情書・意見書案）に書かれている事実だけ**。推測で補わない |
| 書いていないことは書いていないと書く | 理由・経緯・金額などが議案書にない場合は「**議案書には記載されていません**」と明記する |
| 賛否・評価をしない | 「良い／悪い」「賛成すべき」などの評価は書かない。会派の賛否も解説本文には書かない |
| 審議状況は本文に書かない | 可決・否決・付託先などは本文に書かず、「審議の状況は、このページの『審議のステータス』をご覧ください」と案内する（ステータスは取り込みSQLで更新されるため、本文と食い違わないように） |
| 出典リンク | 本文の最後に議案書PDFへのリンクを必ず付ける |
| AI利用の表示 | 本文の最後に「この解説は、議案書をもとにAIで下書きし、運営者が確認したものです。正確な内容は議案書（PDF）をご確認ください。」を付ける |
| 運営者の確認 | 「運営者が確認した」と書く以上、SQLを流す前に運営者がドラフト（Markdown）を必ず読む |

## 2. 個人情報・プライバシー

- **私人の名前は書かない**
  - 請願者・陳情者の氏名、住所、連絡先は書かない（PDFには記載があることだけ触れる）
  - 「訴えの提起」の相手方は書かない（議案書で匿名でも、特定につながる情報は最小限にする）。訴えの目的・経緯の要点のみ書く
- **議員の名前も本文には書かない**
  - 紹介議員・提出議員は「議員の紹介あり」「立川市議会議員7人」のように人数で書く（中立のため。氏名はPDFで確認できる）
- 契約の相手方（法人）など、議案書に記載された公的な契約情報は書いてよい

## 3. 請願・陳情の書き方

- 請願者・陳情者の主張は、市が認めた事実と混同しないよう「**〜としています**」「陳情書では〜としています」と、提出者の主張として書く
- 求めていること（記の項目）は、くわしい版ではできるだけ原文に近い形で並べる
- 個人的な体験談（施設職員の対応など）は、個別の描写を避け「〜などの事例をあげています」と要約する
- 「請願・陳情ってなに？」の説明ブロックをかんたん版に入れる
- スキャン画像のPDFは、ブラウザで画面表示して目視で読む。読めない場合はOCR（Tesseract.js）を使い、**OCRで読んだものは運営者にPDFと照合してもらう**

## 4. 意見書（議員提出議案）の書き方

- 「意見書ってなに？」（地方自治法第99条）の説明ブロックをかんたん版に入れる
- 宛先・求める措置（記の項目）を中心に書く。意見書案の主張は「〜としている」と書く
- 本文が確認できない場合（リンク誤りなど）は、確認できていないことを明記し、間違ったPDFへのリンクは外す（`pdf_url = NULL`）

## 5. 予算・決算の書き方（要点テンプレート）

### 補正予算

- **第1条の総額（補正前・補正額・補正後）を必ず書く**。これは議案書の文章部分で、読み取りが確実
- 款別の内訳や主な事業は、議案書の表（事項別明細書）から書く。ただし**金額を足して総額と一致することを確認できた項目だけ**書く（PDFの表は文字抽出で崩れることが多いため）
- 金額はくわしい版では「千円」単位のまま、かんたん版では「約○億○万円」に直す
- 債務負担行為・地方債の補正があれば別に書く
- ほかの議案と金額が対応しているもの（一般会計の繰出金と特別会計の繰入金など）は、同額であることを事実として補足してよい。理由づけはしない
- 補正の理由が議案書にない場合は「記載されていません」と書く

### 決算

- 議案書が表紙だけで金額がない場合は「金額などの中身は記載されていません」と書く
- 「予算＝計画、決算＝結果」と、認定の手続き（地方自治法第233条第3項、公営企業は地方公営企業法第30条第4項）を説明する

## 6. 構成

### かんたん版

```
## ひとことで
## なにが変わる？（求めていること／主な使いみち など）
## だれに関係ある？／いつから？（議案書に書いてあれば）
## 参考
- [議案書（PDF）](URL)
- 審議の状況は、このページの「審議のステータス」をご覧ください
---
（AI利用の表示）
```

- タイトルは中学生でもわかる言葉で、何が変わるかがわかるように（例：「錦町に新しい公園『錦六北第三公園』をつくる条例改正」）
- 要約は1〜2文

### くわしい版

```
## 概要（表：議案番号・提出日・提出者・提出理由・施行日）
## 改正内容／条例の構成／歳入・歳出 など（新旧対照は表で）
## 補足（議案書に記載のないこと、関連する議案）
## 出典
---
（AI利用の表示）
```

- タイトルは議案の正式名称
- 要約は根拠法令と内容を1〜2文で

## 7. 作業手順

1. **取り込み**：市の「議案一覧」「請願・陳情一覧」ページのHTMLを、PC（デスクトップアプリのブラウザ）経由で取得し、`packages/tachikawa-ingest` でSQLを作る
   - 議案：`pnpm --filter @mirai-gikai/tachikawa-ingest build-sql -- --session <slug> --html <保存したHTML>`
   - 請願・陳情：上記に `--kind petition` を付ける
   - 新しい会期は `packages/tachikawa-ingest/src/masters.ts` の `SESSIONS` に追加する
2. **議案書の読み取り**：ブラウザ内で pdf.js を使って文字を取り出す（作業用コンテナからは市のサイトに直接アクセスできないため）
3. **下書き**：上のルールで、かんたん版・くわしい版をAIとの対話で作る
4. **確認用ドラフト**：Markdownにまとめて運営者に渡し、確認してもらう
5. **SQL**：`bill_contents` を `UPDATE` するSQLを作る（議案番号 `令和8年議案第107号` の形で対象を指定）。PostgreSQLのパーサー（pglast）で構文を確認してから渡す
6. **反映**：運営者がSupabaseのSQL Editorで流す
7. **記録**：流したSQLは `supabase/seed-tachikawa/contents/<会期>/` に保存する

## 8. チェックリスト（SQLを渡す前）

- [ ] すべての解説に PDF リンク・「審議のステータス」の案内・AI利用の表示がある
- [ ] 本文に「可決」「否決」「付託」など審議結果の記述がない
- [ ] 私人の氏名・住所がない（請願者・陳情者・訴えの相手方）
- [ ] 議員の氏名がない
- [ ] 予算の金額は総額と整合を確認した項目だけ
- [ ] 議案書にない情報を補っていない（一般的な制度説明は、法律名を示して最小限）
- [ ] SQL がパーサーで通る
