# 議員ページ テーブル設計案

作成：2026-11-27（案。運営者の確認後にマイグレーションを作る）
前提：`docs/20261127_0725_議員ページ設計.md`（方針・載せるもの・選挙期間中の扱い）

## 方針

- 既存のテーブル（`factions`・`council_sessions`・`bills`）はそのまま使い、議員まわりのテーブルを足す
- **履歴を残す**：会派の所属、議長などの役職、議席番号は変わるので、期間つきで持つ。過去の会期の一般質問は、その当時の会派・議席で表示できるようにする
- **原文と出典を残す**：一般質問の件名・小項目は原文のまま保存し、出典URLと取得日を持たせる
- 評価・集計のための列（回数・スコアなど）は作らない
- RLS は有効にし、ポリシーは定義しない（他のテーブルと同じ。アクセスは Service Role 経由）
- 取り込みは、これまでと同じく「生成した SQL を SQL Editor で流す」。何度流しても同じ結果になるようにする

## テーブル

### 1. `council_members`（議員）

| 列 | 型 | 内容 |
|---|---|---|
| id | uuid PK | |
| slug | text NOT NULL UNIQUE | URL・取り込み用（例：`hiyama-shogo`） |
| name | text NOT NULL | 表示名。市議会公式「50音順議員名簿」の表記（例：`ひやま 昇吾`） |
| name_kana | text NOT NULL | 50音順に並べるための読み |
| sort_order | int NOT NULL | 50音順の並び（名簿の順） |
| official_profile_url | text | 市議会の名簿ページ |
| homepage_url | text | 本人HP（本人が公開しているもの） |
| x_url | text | 本人X（本人確認できたもの） |
| links_checked_at | date | HP・Xを確認した日 |
| is_current | boolean NOT NULL | 現職か（改選・辞職で false） |
| created_at / updated_at | timestamptz | |

- 取り込みとURL用に `slug`（例：`hiyama-shogo`、`UNIQUE`）を持つ。同姓同名が出たら slug に区別を足す
- 応援アカウント・報道など本人以外のURLは入れない

### 2. `council_member_terms`（任期・議席）

| 列 | 型 | 内容 |
|---|---|---|
| id | uuid PK | |
| member_id | uuid FK → council_members | |
| term_start | date NOT NULL | 任期の始まり（例：2026-06-xx） |
| term_end | date | 任期の終わり（任期中は null） |
| seat_number | int | 議席番号 |
| end_reason | text | 任期満了・辞職など（事実のみ） |

### 3. `council_member_factions`（会派の所属の履歴）

| 列 | 型 | 内容 |
|---|---|---|
| id | uuid PK | |
| member_id | uuid FK | |
| faction_id | uuid FK → factions | |
| start_date | date NOT NULL | |
| end_date | date | 所属中は null |
| source_url | text | 根拠（市議会だより・名簿など） |

- 例：いしとび議員は「都民ファーストの会立川市議会」→「立川の未来」（第343号から）
- 1人会派も `factions` に登録する（2026-11 の決定どおり）。現在の `masters.ts` の `FACTIONS` には「立川の未来」「日本保守党」が無いので追加する

### 4. `council_member_roles`（議長・副議長などの役職）

| 列 | 型 | 内容 |
|---|---|---|
| id | uuid PK | |
| member_id | uuid FK | |
| role | text NOT NULL | `議長`・`副議長` など |
| start_date / end_date | date | |

- 議長の在任期間中は、議員ページに「議長は慣例として一般質問を行わず、採決にも加わりません」の補足を出す（在任期間ごと）

### 5. `general_questions`（一般質問：議員×会期で1件）

| 列 | 型 | 内容 |
|---|---|---|
| id | uuid PK | |
| member_id | uuid FK | |
| council_session_id | uuid FK → council_sessions | |
| order_number | int NOT NULL | 受理番号（質問の順番） |
| seat_number | int | その時点の議席番号（原文） |
| faction_label | text | その時点の会派名（順序表の表記のまま） |
| question_style | text | `一問一答`・`一括質問` |
| aids | text[] | `モニター`・`パネル` など（順序表の備考） |
| question_date | date | 質問した日（日程表・会議録で確定したら入れる） |
| source_url | text NOT NULL | 一般質問順序表のPDF |
| source_fetched_at | date NOT NULL | 取得日 |
| minutes_url | text | 会議録が公開されたら、その日の会議録へのリンク |

- 一意キー：`(council_session_id, member_id)`
- 通告が無かった議員は行を作らない（ページでは「今回の定例会では一般質問の通告はありません」と表示。議長の期間は議長の補足を表示）

### 6. `general_question_items`（件名と小項目）

| 列 | 型 | 内容 |
|---|---|---|
| id | uuid PK | |
| question_id | uuid FK → general_questions | |
| parent_id | uuid FK → general_question_items | 小項目のときは件名の id。件名は null |
| item_number | int NOT NULL | 件名は「１」「２」、小項目は「①」「②」の番号 |
| text | text NOT NULL | 原文のまま（誤字も含めて直さない） |
| sort_order | int NOT NULL | |

- 件名だけ／小項目だけで検索・タグ付けできるよう、2階層を同じテーブルで持つ
- テーマの分類（タグ）を付ける場合は、運営側で付けたものと分かるように別テーブル（`general_question_item_tags`）にする。今回は作らない

### 7. `council_member_pledges`（掲げたテーマ）

| 列 | 型 | 内容 |
|---|---|---|
| id | uuid PK | |
| member_id | uuid FK | |
| text | text NOT NULL | 本人が掲げているテーマ（短く） |
| source_type | text NOT NULL | `本人HP`・`選挙ドットコム本人登録欄`・`本人X` など |
| source_url | text NOT NULL | |
| checked_at | date NOT NULL | |
| sort_order | int | |

- 選挙公報は市のサイトに未掲載のため、現時点では `source_type` に入らない

### 8. `election_blackouts`（選挙期間中の非公開）

| 列 | 型 | 内容 |
|---|---|---|
| id | uuid PK | |
| election_name | text NOT NULL | 例：`2030年 立川市議会議員選挙` |
| start_date | date NOT NULL | 告示日 |
| end_date | date NOT NULL | 投票日 |
| member_id | uuid FK | null なら議員ページ全体を閉じる（市議選）。値があればその議員だけ閉じる（ほかの選挙に立候補した場合） |

- 期間中は、議員ページの代わりに閉鎖中の表示を出す。議案・賛否・会議録へのリンクなど議会の記録は表示を続ける

## 画面とルート（案）

| ルート | 内容 |
|---|---|
| `/members` | 議員一覧（50音順。会派・本人のHP/Xへのリンク） |
| `/members/[slug]` | 議員ページ（掲げたテーマ、一般質問の件名・小項目〈会期ごと、新しい順〉、所属会派の賛否、本人の発信へのリンク） |
| `/sessions/[slug]/general-questions` | 会期ごとの一般質問の一覧（質問の順番どおり） |

- 回数・件数の比較や並べ替えの機能は付けない

## 取り込み

1. 一般質問順序表のPDFを手元で表として読み取り、JSON（`supabase/seed-tachikawa/source/r8-4-general-questions.json`）に保存する（AI不使用。PDFの表をそのまま読む）
2. `tachikawa-ingest` に、JSON から `general_questions`・`general_question_items` の SQL を作る処理を足す
3. 議員・任期・会派の所属は、市議会の名簿と議会だよりを見て `masters.ts` に手で書く（会派と同じ扱い）

## 決めてほしいこと

1. 議員の読み（`name_kana`）は、名簿にふりがなが無い場合に運営側で付けてよいか
2. 一般質問の会期ごとの一覧（`/sessions/[slug]/general-questions`）も作るか（議員ページだけにするか）
3. 過去の一般質問（令和8年第1・2回など、改選前の分）を会議録から入れるか。入れる場合、改選前の議員（今は議員でない人）も `council_members` に入れることになる
